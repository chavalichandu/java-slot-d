# Task 10 — Encapsulation, Packages and Access

**Aim:** Protect state and describe how Java packages organise a larger
implementation.

Vehicle, user, ticket and facility fields are private; constructors and
public methods validate state changes. Protected members are used where a
subclass needs access. Package structure such as `parking.model`,
`parking.service` and `parking.app` is discussed in the report, but the
required standalone programs intentionally remain in the default package so
their documented one-file compile commands work.

See Task 10 in `../Assignment_Report.md` for access levels, wrapper types,
encapsulation and the package layout.
